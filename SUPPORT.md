# Support policy

## Public repository support

Use GitHub issues for reproducible defects, documentation gaps, and repository-scoped feature requests. Search existing issues first and include the affected commit or version, environment, expected behavior, actual behavior, and minimal reproduction steps.

Never post credentials, access tokens, private customer data, private store or domain details, commercial documents, or vulnerability exploit details in a public issue. Security matters must follow [`SECURITY.md`](SECURITY.md).

## Authorized repository representative

The repository owner and default CODEOWNER, `@waseem99`, is the authorized repository-side representative for support triage, release provenance, and decisions about this codebase and its generated artifacts.

## Live systems and commercial pilots

Authorization for a WordPress domain, Shopify store, hosted deployment, customer workspace, or commercial pilot must be obtained from the actual system or business owner through an approved private channel. GitHub repository ownership does not by itself establish authority over those external systems.

The external representative record should identify the system, representative, authority basis, approved scope, date, and evidence location without committing confidential evidence to this public repository.
